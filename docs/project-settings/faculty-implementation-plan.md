## 已确认的方向

- 第一阶段：天文与天体物理研究部全体教师，加其他研究部的天文相关教师。
- 定期更新：任职单位、职称、研究方向、个人主页、代表论文。
- 产品入口：尺度图与可检索名录并重。
- 教师身份：研究员、副研究员、助理研究员及双聘全部纳入；博士后、访问学者、工程师暂不纳入。行政岗位不属于本项目教师范围。
- 发布方式：每周自动生成变更清单，由用户或维护者审核后发布。现阶段所有公开内容变更均走审核，不设未经确认的自动发布例外。
- 全球覆盖：人人可进入名录；完成可靠标注后再进入尺度图。名录完整性与尺度图覆盖率分别验收。
- 跨部标准：官方研究方向明确涉及天文、宇宙学、天体粒子、暗物质或中微子，满足其中一项即纳入，标注具体关联。无需额外证明暗物质或中微子课题直接面向某个天体。
- 首版必备资料：每人的身份、职称、研究方向、官方链接和来源证据必须齐全；简介与代表作逐步补充，不作为首版完成的前置条件。
- 语言：中文界面为主，保留原文姓名、职称和研究方向；英文简介逐步补充。不要求每个人都有中文译名或中英对等长简介。
- 审核载体：GitHub Pull Request，查看差异与证据，人工批准并合并后发布；不启用自动合并。
- 检查时间：每周一北京时间 09:00（Asia/Shanghai，UTC 周一 01:00）。你按需审核；未审继续展示上次已发布版本。执行时先完成手动及故障验证，再启用这一周期。

## 1. 当前系统和实际缺口

网站的特色是把研究者研究的天体范围映射到尺度—质量图，点击查看简介与论文；不是按引用量排名的学者搜索引擎。建议保留暖色星图、研究区域、尺度之外和详情页这套表达。

已阅读 README、data 文档与 JSON、docs/project-settings 全部设定，以及类型、数据加载、主页/详情/星图/侧栏、检查脚本、部署配置等核心文件。现有 23 位研究者、37 个天体；14 位在图上，9 位在尺度之外。React/Vite 静态站构建时整包导入 JSON，每人使用 SVG 区域与 DOM 头像。尚无独立机构、任职历史、字段证据、核验时间、采集运行记录或国家地区筛选模型。

本轮 `npm run check:data` 与 `npm run build` 均通过。它们能说明当前数据满足现有规则、项目能构建，不能说明名单完整或事实准确。检查脚本反而要求每人必须有照片与论文；这会阻碍“身份已核实但资料未齐”的人先进入名录。

README 说 main 推送会触发 Pages 发布，但本地工作流是 `.github/workflows/deploy-pages.yml.disabled`；因此不能据 README 认定当前已有可运行的自动发布链路。需要执行阶段检查实际 GitHub Pages 配置；当前没有查验远端工作流运行历史。

## 2. 第一优先级：能解释“为什么说收全了”

先发布收录政策。按用户第二轮确认，天文部学者系列、研究员系列与双聘全部纳入；博士后、工程师、访问学者暂不纳入，行政岗位不属于教师范围。退休、兼职等身份单独记录；建议历史信息保留，默认“现任”视图不含已确认离任或退休者，兼职以明确角色展示。跨部按第三轮确认：官方研究方向明确涉及天文、宇宙学、天体粒子、暗物质、中微子任一类别即可纳入；保存原文与对应关联标签，不另加“必须有直接天文应用”的门槛。

边界例：只写“粒子物理”不能据此自动纳入；明确写“暗物质对撞机探测”或“中微子实验”则符合已经确认的宽口径，即使未写具体天体。某篇论文偶然出现相关词、获奖新闻提到相关主题、自动作者画像给出相关标签，都不能替代官方研究方向证据。中文/英文页面中明确的等价学术术语均可作为证据，机器匹配只用于形成待审候选。

建立逐人对账账本：稳定人员 ID、官方姓名、来源目录与个人页、原始身份、是否属于范围、纳入/排除理由、对应网站 ID、核验人及日期。每个官方候选必须有去向；同一人只保留一个实体，可以有多个部门和任职。

区分三个完成度：名录已收录、首版必备字段已核验、尺度标注已审核。没有头像、没有论文列表或没有合适尺度区域，不应阻止已核实人员入库。按第三轮确认，首版每人必须具备已核实姓名与身份/任职机构、职称、研究方向、可访问的官方链接、支持这些字段的来源与核验信息。邮箱可选，ORCID 可选；中文译名、简介、代表作、荣誉、头像和区域均可后补。

名单页没给研究方向时，继续查官方个人页或该页链接的本人研究站点；不能用“研究方向待补充”占位来通过“首版必备资料齐全”的验收。确实找不到时进入缺项账本，明确说明首版尚未全部完成；资料缺失不应通过编造简介或用论文标签冒充官方自述来解决。

第一阶段验收：选定日期与口径下，所有应纳入人员均能在名录找到；所有候选都有明确处理结果；不存在无解释的漏项和重复人员；核心身份字段逐人有证据。公开“完整覆盖”前关闭影响收录边界的未决项。这个结论仅对应公开官方名录与本次核验时间，不能保证发现官网本身未公布的人。

首轮对账的具体交付应包括：天文部 27 人的完整对应表、9 名缺项的补录资料、6 名地址编号不一致者的别名与匹配证据，以及跨部全体候选的判断账本。最终首版人数等于天文部基线与审核合格的跨部人员并集，按人员去重；不能预先写成“27＋6”或其他已知候选的简单加总，现有跨部人员也需按统一规则复核。

## 3. 数据模型：人员、任职、机构、证据和尺度标注分开

短期仍可使用 Git 管理的 JSON，不必立即上数据库，但数据边界现在就要拆清楚。

- Person：本站稳定 ID、原文姓名、姓名别名、可选中文名、可选 ORCID/OpenAlex ID 及其匹配审核状态。没有 ORCID 也可以入库。现有 `/mentor/:id` 保持可访问；以后引入更长 ID 时通过别名兼容旧地址。
- Organization：本站机构 ID、多语言名与别名、类型、官网、地点、可选 ROR、父子/关联机构关系。研究部未必有 ROR，不强制伪造；大学、研究所、院系不是一个扁平字符串。
- Affiliation：personId、orgId、原始职称、规范角色、主聘/双聘/兼职、开始/结束日期（允许未知）、是否现任及证据。一个人可以同时关联多个机构，退休与离任不删除历史。
- Evidence/Claim：实体与字段路径、支持的值、sourceId、定位信息/必要的简短摘录、获取时间、内容指纹、来源更新时间（若有）、核验时间、审核人、处理状态。事实有冲突时保留不同来源及选择理由。
- Paper：稳定论文 ID、题名、期刊/年份、DOI/arXiv 等可选标识、来源、与人员的关联证据。论文单独保存，人员关联“代表作”列表及选取来源；未来若加近期论文，另设列表。
- AtlasAnnotation：personId、研究主题、当前手画 regions/anchor/pigment、关联天体、说明、证据、方法和审核版本。几何字段只属于图谱层。区分“已审核”“待标注”“无适用尺度”，不能把待处理伪装成不适用。
- Source/SyncRun/Coverage：来源入口和解析器版本、预期页面结构、每次运行结果、异常、机构覆盖口径和核验范围。

避免设置一个包办所有含义的 status。任职状态、数据审核状态、图谱标注状态、采集来源健康度分别记录。抓取时间 fetchedAt/checkedAt、事实变更时间 changedAt、生效日期 effectiveAt、人工核验 reviewedAt 各有含义；重新抓到网页不等于完成了人工核验。

机构与国家地区筛选按当前任职地点归属，不按国籍。国家/地区编码与显示名称分离，允许多地点；大学筛选默认包含下属已收录单位。一个人多重任职命中多个单位时，结果列表按 personId 去重；地区与机构组合必须由同一条任职链同时满足，避免将“中国任职＋哈佛兼职”的人误算为“哈佛在中国”。

## 4. 信息可靠性：按字段选择来源

人员范围与任职：官方成员名录、研究部页面、个人主页交叉验证。不能把论文署名单位直接当现任单位；ORCID 的单位信息也需要区分本人填写与机构添加的来源。官方页面出现冲突时保留原文、挂待核实并人工判断，而不是固定相信最新抓到的一页。

研究方向：官方研究简介优先，个人研究站点补充。原文与本站整理/翻译分别保存；机器生成摘要须可追溯且经过审核，不产生无来源的事实。

中文界面不等于给所有内容强制补译。姓名、职称、研究方向保存其来源语言与原文；中文标签和检索别名作为另一层。没有官方中文名的人显示原文姓名；职称保留原始职级，同时提供必要的中文类别说明，不强行把海外职级换算成中国职称。第一版不新增“每人中英长简介必须齐全”的要求，已有可靠双语内容可以保留。

代表作：优先官方个人页或本人列出的 selected publications；保留原列表与可解释选取规则。最新论文、最高引用论文与代表作不是同一概念。OpenAlex 适合补充可再利用的文献元数据，但先审核作者 ID，防止同名、作者合并和拆分。DOI/arXiv 去重；疑似重复或只有近似题名的条目进入复核，不自动关联。

机构：ROR 适合提供机构标识、别名、地点与组织关系，本地补足院系和研究所粒度。ROR 不是“所有天文机构/教师”的完整目录。

图谱：现有色块是编者判断，继续清楚标注“研究范围示意”，附依据与方法版本。没有证据时不把主题词自动转换成精确物理边界。

头像：已知来源不等于已获使用许可。建议新增条目支持姓名/印章回退，逐步补充获准使用的头像与权利信息，避免把照片成为全球收录的前置条件。保存元数据和必要的短证据；网页全文快照是否保存、保存多久以及是否公开，应随来源规则制定。

页面提供“来源与核验”区域：官网直达、核心字段最后核验日期、待核实项、图谱说明、纠错入口。未知就显示未提供或省略，不能根据没有信息推导“无招生/已离职/无成果”。本轮确认的范围不包含招生名额、招生意愿与近期新闻流。

## 5. 周一更新：采集、比较、审核、发布

已确认采用 GitHub PR 审核后发布。自动化的终点是生成待审变更 PR，不直接修改线上公开教师数据，不自动合并。检查时间为每周一 09:00（Asia/Shanghai，对应 UTC 周一 01:00）。你或维护者按需审核，未审核时线上继续使用旧版。这个周期已确认为实施需求，但本轮没有创建调度。GitHub Actions 执行可能延迟，因此 09:00 是计划触发时间，不是承诺完成时间。

流程：列举来源 → 有节制地抓取/缓存 → 结构校验 → 解析规范化 → 身份匹配 → 字段级差异 → 生成带证据的变更提案 → 校验与审核 → 构建版本 → 发布并保留回滚版本。

- 抓名录才能发现新人；只刷新已有 23 人的主页无法保证持续收全。
- 无变化也记录检查成功时间；通知仅在有变化、来源失败或需要处理时产生。
- 代表作更新不覆盖人工解释、译文、研究区域和人工指定的选文理由。编辑层与采集层分开存储，人工修正可锁定并复核。
- 页面缺席、404、超时、空白 HTML 都不能自动等同离任。新增/删除、职称/任职变更、作者身份冲突、明显数量骤变进入复核；需要明确的官方证据才能确认离任，生效日期未知则保留未知。
- 200 响应仍要校验正文、栏目结构、人员数量与分页是否齐全；源站结构变化时停止该来源更新，不发布空名录。
- 失败来源保留上次成功版本并标记未更新，成功来源可形成独立提案；最终发布的是经过一致性校验的完整版本。记录每个来源的成功率与待处理问题，不能只报一次任务总体成功。
- 可重复运行、重试退避、来源限速、并发锁、运行日志；API 密钥只放采集环境，不进入前端 bundle。

建议先手动运行一次完整流程，再用历史快照演练一次变化与一次失败，最后启用每周调度。连续 4 次成功周更可作为稳定运行里程碑，无需为了等满四周阻塞第一版名录上线。

审核清单建议对每次变化展示：人员、字段、线上旧值、建议新值、官方来源与定位、检查时间、变化类型、冲突提示及依赖项。维护者可以接受、驳回、暂缓；暂缓项不影响线上旧值。相互依赖的身份、机构与任职变更应成组审核，避免只接受姓名而遗漏必要的机构引用。只有完成审核和发布后，才更新该字段的公开版本；一次新抓取或一份未审清单不会把“最后人工核验”刷新为今天。

审核载体已确认为 GitHub PR。每份 PR 包含覆盖差异概览、字段旧值/新值、对应官方证据、检查结果及需特别关注的冲突。维护者可编辑、删除或暂缓具体变更，待保留内容校验通过后人工合并；不为“逐字段接受”额外建设网站后台。审核人未处理时仍可运行下一次检查；复用一个未合并的数据更新 PR，按实体与字段归并待审差异，避免每周重复开单。若 PR 内容更新，重新运行校验并要求审核最新提交，不能沿用旧版本审核结论。这里的审稿人是用户或指定维护者，不隐含要求当前规划 agent 每周自主运行。

运行日志自动记录检查成功、失败与无变化；这些记录与已审核教师数据分开。无变化不为了刷新时间戳生成教师数据 PR；网站展示已发布数据对应的核验/发布日期，并提供 GitHub 核查运行记录链接。若展示来源健康度，应说明它对应哪次已发布记录，不能把旧网页上的时间称为“本周刚完成检查”。

## 7. 实施阶段与交付验收

P0／收录基线：确定范围；遍历天文部与跨部候选；完成对账与地址别名；先补最小可靠条目。交付 coverage 账本、来源证据、纳入排除理由及缺字段清单。通过标准是应收录人员无漏项，不是人人有完整长简介。

P0 的字段验收也需满足用户确认的首版必需项：身份、职称、方向、官方链接、来源全部齐。对齐首版必需项后可以验收，不等待简介、代表作或英文简介补齐。现有照片/论文必填校验须改为适配这种条目层级，不能直接删除所有数据质量检查。

P1／可靠数据与名录：将人员任职、机构、证据、图谱标注解耦；提供名录、来源日期、共用筛选；保留原 23 人路由、图谱与动效。允许最小条目缺论文/照片；建立运行时 schema 校验和引用完整性检查。通过标准是中英文同人不重复、多重任职正确、两视图计数一致、未知字段不造假。

P2／每周更新：来源适配器、差异提案、审批边界、发布与回滚、来源健康度、手动和定时触发。验收使用真实已核验基线加测试快照：新增一人、角色变更、一页失败、网页返回空正文、分页缺失、中英文地址变化都不造成静默漏人或删人；无变化再次运行不产生无意义内容差异。

P3／少量机构试点：先选 2–3 个不同结构的单位，至少覆盖国内大学院系、研究机构、海外院系；若有优先名单由用户指定。每个单位登记官方名单入口、适配器、收录政策和覆盖时间。验收跨机构同人合并、下属单位展开、国家地区与机构联合筛选、来源失败隔离。先验证可维护性，再承诺大范围覆盖。

P4／全球扩展：按机构逐批收录，区分“已核验机构”“部分覆盖”“仅发现候选”，公开覆盖地图/清单和维护进度。不能以论文作者库或 IAU 会员直接声称收全全球教师。对规模化名录做索引与分片加载，按实际测量决定服务端检索、数据库、Canvas/WebGL 图层和聚合；保留可访问的列表作为等价入口。

建议初期保留 React/Vite、静态托管与 Git 审核。数据由离线脚本产生公开 JSON/索引，前端消费发布版本，不直接请求每个官网。需要多人后台编辑、待审事件显著堆积或数据/查询实测超出静态方案时，再迁移数据库与任务队列。不要仅因为“将来全球”立即重写全部系统。

性能验收在执行前约定设备、网络和数据规模。建议分 100、1000、10000 人合成集评估首屏传输、筛选响应、缩放帧率与可访问性，再设预算；不能把“超过某人数一定卡”当成已经测量的结论。

## 8. 给执行 agent 的边界

执行顺序建议是 P0 → P1 → P2，完成后再扩机构。P0 可以为最小条目做必要的数据字段松绑，但不以收全为由编造头像、代表作或研究区域。验收必须对官方候选账本，不可将现有 mentors.json 作为完整性测试的唯一分母。
